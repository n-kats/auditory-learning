## 決定事項
- 既存の PDF アプリとは別に、`quick-auditory-learning/` を独立した実験用プロジェクトとして作る。
- 入力データはローカル JSONL を前提にし、起動時または別コマンドでインポートできるようにする。
- 永続データは `_data/quick_auditory_learning/`、キャッシュは `_cache/quick-auditory-learning/` に分ける。
- 音声は DB に残さず、必要な分だけキャッシュする。
- session は WebSocket で進行し、`playback_sessions` / `session_events` / `session_trail_items` で現在値とイベントログと trail を分けて持つ。
- 検索・ベクトル化・解説作成・音声作成・次候補先行実行は、依存しない部分を最大限並列化する。
- 解説作成の先行実行は、アクティブな session 数程度に制限し、何ステップも先まで走らせない。

- 埋め込みモデル版の外部設定を廃止し、内部版は自動管理するように寄せた。
- 埋め込みモデル名の既定値を `text-embedding-3-large` に統一した。
- 起動時の全件ベクトル化は行わず、検索時に必要になった候補論文だけを埋め込み生成してキャッシュするようにした。

- 検索処理に候補数と埋め込み生成数のログを入れ、結果が空になる理由を backend.log で追えるようにした。
- 検索ヒットがない場合はランダムな論文を返して止まらないようにし、不採用候補は簡易表示するようにした。
- 論文選択時に解説は DB に保存し、音声は失敗しても止めずに準備を試みるようにした。
- 検索結果の上位数件は、解説と音声を先読みするようにした。
- 開始点は arXiv URL の論文にし、DB にあればそこから、なければ arXiv API から取得するようにした。
- 次の論文へ進むときは、前の論文を除外するのではなく、直前の論文の title/abstract から検索語を作って再検索し、再生トレイル内の論文を除外する。

- `voicevox` のホスト公開はやめ、compose 内部通信のみで使うようにした。
- 音声生成失敗時の例外メッセージに VOICEVOX の接続先 URL と speaker_id を含めるようにした。
- `launch_quick_auditory_learning.sh --dev` の VOICEVOX 既定値を docker 内の `http://voicevox:50021` に修正した。

- UI の音声再生は chunk 単位でも連続再生に見せ、最後まで再生したら現在の論文の title/abstract から検索語を作って再検索し、再生トレイル内を除外しながら次の論文へ自動で進み、停止ボタンだけで止められるようにした。
- WebSocket で session を開始し、session state / event log / trail を DB に分けて持つようにする。
- 画面の「濃さ」は背景と半透明カードの重なりで出ている可能性が高いので、まず背景だけを軽くする。
