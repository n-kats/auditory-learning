# ワークフロー追加ガイドライン

本ドキュメントは、新しいワークフローをリポジトリに導入する際の手順と記録方法を定義します。外部 URL や別資料で
指定された運用ルールを取り込み、`AGENTS.md` と `docs/workflows/` を同期させることを目的とします。

## 目的と適用範囲

- Codex エージェントが新たな開発フローや運用手順を確実に共有・再利用できるようにする。
- 外部資料を参照したワークフローを、このリポジトリの標準的な形で文書化する。
- 追加時点で既存ワークフローとの重複や矛盾を防ぎ、`AGENTS.md` のワークフロー節を常に最新化する。

## 適用シナリオ

- ユーザーから URL や資料へのリンクを渡され、内容をもとにリポジトリへ新しいワークフローを組み込みたい場合。
- 既存の開発フローに不足があり、自主的に共通手順を整備する必要が出てきた場合。
- 他ドキュメントへ新しいフローを追加する前に、標準化されたプロセスでガイドラインと要約を整えたい場合。

## 事前準備

1. **現状把握**  
   - `docs/directory_structure.md` で関連資料の配置場所を確認する。  
   - `AGENTS.md` の「ワークフロー」節と既存の `docs/workflows/*_guidelines.md` を読み、同種の内容がないか把握する。
2. **元資料の収集**  
   - ユーザー指定の URL や添付資料をすべてローカルに保存し、参照箇所を明示する。  
   - 必要に応じて要点メモを作成し、後続のドキュメントに引用できる形にまとめる（直接コピーではなく要約する）。

## 追加手順

1. **メタドキュメントの作成**  
   - `docs/workflows/` に `<workflow_name>_guidelines.md` を新規作成する。  
   - 以下のテンプレートを用い、外部資料を要約しつつこのリポジトリ向けの指針に書き換える。  
   - 専門用語は必ず定義し、実行手順を箇条書きで明確にする。
2. **AGENTS.md の更新**  
   - 「ワークフロー」節に新しい小項目を追加し、**目的・トリガー（または適用例）・詳細**の三点セットで要約する。  
   - 「詳細」は「`docs/workflows/...` を参照。このワークフローを実施時に必ず参照すること。」の形式に統一する。
3. **関連ドキュメントの確認**  
   - 必要に応じて `docs/implementation_status.md` の Documentation 項目へタスクを追加または完了済みとして記録する。  
   - 既存のドキュメントと矛盾がないかを確認し、差分レビューで説明できるようにする。

## メタドキュメント用テンプレート

````md
# <ワークフロー名> ガイドライン

## 目的
- このワークフローの狙い: …
- 想定する利用シナリオ: …

## 参照元資料
- 出典: URL または資料名（要約を添える）
- 重要ポイント: …

## 実施手順
1. …
2. …

## 成果物
- `AGENTS.md` への記載内容: …
- その他更新するドキュメント: …

## 注意事項
- …
````

## AGENTS.md 用スニペット例

```md
- **<ワークフロー名>**  
  - **目的**: …  
  - **トリガー**: … / **適用例**: …  
  - **詳細**: `docs/workflows/<workflow_name>_guidelines.md` を参照。このワークフローを実施時に必ず参照すること。
```

## 受け入れ基準

- `docs/workflows/` に新しいガイドラインファイルが追加され、目的・手順・テンプレートが揃っている。  
- `AGENTS.md` の「ワークフロー」節に対応する短い説明が追加されている。  
- 元資料の内容が要約され、依存関係や注意点が明示されている。  
- 追加したワークフローを読むだけで、他の開発者が同じ手順を再現できる。
